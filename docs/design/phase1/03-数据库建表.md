# 第一阶段详细规格 第 3 节：数据库建表清单

范围：公司站点、产品、库存账本、用户角色权限审计、Excel 导入导出、设备同步，加导入审批用的最小 approval_request。共 27 张表加 1 张配置表。

## 命名和类型约定

| 约定 | 规定 |
|---|---|
| 表名字段名 | 小写下划线，表名单数 |
| 主键 | id uuid，客户端生成 UUID v7 |
| 公司隔离 | 除全局表，每表第二列 company_id uuid 非空 |
| 数量 | numeric(14,3) |
| 金额 | numeric(14,2) |
| 时间 | timestamptz 存 UTC |
| 文本 | text 加长度 check |
| 枚举 | text 加 check，不用 enum 类型 |
| JSON | jsonb |
| 审计列 | created_at/by, updated_at/by，触发器填 |
| 软删除 | is_active，不用 deleted_at |
| 外键 | 全部声明，ON DELETE RESTRICT |
| 唯一 | 带 company_id 复合唯一 |

## 第三组：库存和账本

### movement
| 字段 | 类型 | 约束 |
|---|---|---|
| id | uuid | PK 客户端生成 |
| company_id, product_id | uuid | FK |
| from_location_id, to_location_id | uuid | FK，CHECK from ≠ to |
| qty | numeric(14,3) | >0 |
| reason | text | check in ('RECEIVE','PUTAWAY','REFILL','TRANSFER_OUT','TRANSFER_IN','SALE','RETURN','COUNT','ADJUST') |
| ref_type | text | check in ('IMPORT','GRN','TRANSFER','SALE','COUNT','ADJUST','MANUAL') |
| ref_id | uuid | 不做 FK |
| expiry_date | date | |
| unit_cost | numeric(14,2) | 服务器从 product 复制 |
| performed_by | uuid | FK user |
| performed_at | timestamptz | 业务时间 |
| device_id | uuid | FK |
| client_created_at | timestamptz | |
| synced_at | timestamptz | 默认 now() |
| note | text | ≤200 |
| reversal_of | uuid | FK movement |

规则：
- 第一阶段只启用 RECEIVE, PUTAWAY, REFILL, COUNT, ADJUST，由 movement_reason_enabled(company_id, reason, enabled) 控制。
- 两位置同 company。
- 跨站点只允许 TRANSFER_* 且一端 TRANSIT，第一阶段拒绝。

索引：(company_id, product_id, performed_at desc)；(company_id, from_location_id, performed_at desc)；(company_id, to_location_id, performed_at desc)；(company_id, performed_by, performed_at desc)；(ref_type, ref_id)；(company_id, reason, performed_at)。

只插入：触发器拒绝 UPDATE/DELETE，错误"移动记录不可修改，请插入反向记录"。应用账号不授 UPDATE/DELETE。

### stock
(product_id, location_id) PK, company_id, qty 默认 0 允许负, last_movement_at, earliest_expiry。索引 (company_id, location_id)；(company_id, product_id)；(company_id) where qty < 0。应用账号只 SELECT，只有 SECURITY DEFINER 触发器函数写。

### Movement 触发器（AFTER INSERT 每行）
1. 校验两位置 company_id = movement.company_id。
2. 校验 reason 在 movement_reason_enabled 启用。
3. 校验 performed_by 有该 reason 权限（user_site_role + role_permission）。
4. from：UPSERT stock qty 减，last_movement_at 取大。
5. to：UPSERT stock qty 加，expiry_date 早于 earliest_expiry 则更新。
6. from 变负且 settings.allow_negative_stock = false 且 reason ≠ SALE → 抛"库存不足"。SALE 永远允许负。
7. COUNT/ADJUST 到 DAMAGED → 损耗刷新队列钩子（第二阶段）。

UPSERT 用 ON CONFLICT DO UPDATE，两行按 location_id 排序执行防死锁。

### expiry_lot
id, company_id, product_id, location_id, expiry_date, qty ≥0。UNIQUE (product_id, location_id, expiry_date)。收货加，盘点重置，其他不碰。

### shelf_assignment
id, company_id, product_id, location_id（触发器检查 site.type = SHOP 且 zone_type = SHELF）, is_primary, facing_count, assigned_by, assigned_at。UNIQUE (product_id, location_id)；每产品每店一个 primary（触发器）。

## 第十组：用户、角色、权限、审计

### app_user
id, company_id, name, phone（公司内唯一）, email, pin_hash（argon2id）, pin_failed_count（5 次锁 15 分钟）, pin_locked_until, badge_code（16 位随机，公司内唯一）, language check in ('zh','ms','en'), font_scale 1.00 或 1.25, telegram_user_id, photo_url, is_active。

### role
id, company_id（空 = 系统模板）, code（九个）, name_zh/ms/en, home_buttons jsonb 最多 4 个 {screen, icon, color}。UNIQUE (company_id, code)。公司创建时复制启用角色。

### permission
code PK, description, phase。全局。第一阶段约 40 个。

### role_permission
(role_id, permission_code) PK, condition jsonb 可空如 {"own_site_only": true}。

### user_site_role
user_id, site_id 可空（全公司）, role_id。表达式唯一索引 (user_id, coalesce(site_id, 零 UUID), role_id)。

### approval_request（最小版）
id, company_id, type（第一阶段只 'IMPORT'）, ref_type, ref_id, requested_by, approver_role_id, approver_id, on_behalf_of, delegation_id, status check in ('PENDING','APPROVED','REJECTED','RETURNED'), decided_at, decision_note。CHECK requested_by ≠ approver_id。

### audit_log
id, company_id, user_id 可空, action check in ('INSERT','UPDATE','DELETE','LOGIN','LOGOUT','EXPORT','APPROVE','REJECT'), table_name, row_id, before_json, after_json, changed_columns text[], ip inet, device_id, at。只插入，按月分区。触发器挂：company, site, zone, location, category, tax_code, supplier, product, barcode, app_user, role, role_permission, user_site_role, shelf_assignment, import_job, approval_request。movement 不审计。会话变量 app.user_id / app.device_id / app.company_id 传给触发器。

## 第十一组：Excel

### import_template
code PK（PRODUCT, BARCODE, SUPPLIER, OPENING_STOCK, LOCATION, CUSTOMER）, version, sheet_name_zh/ms/en, columns jsonb, required_permission FK。全局。

### import_job
id, company_id, file_url, file_hash sha256, file_name, uploaded_by, status check in ('UPLOADED','VALIDATING','VALIDATED','PENDING_APPROVAL','APPLYING','APPLIED','REJECTED','FAILED'), sheets_summary jsonb, approval_request_id, approved_by, applied_at, error_message。

### import_row
id, job_id FK, sheet_code, row_no, raw_json, normalized_json, status check in ('OK','WARNING','ERROR'), messages jsonb [{column, level, text_zh, text_ms, text_en}], action check in ('CREATE','UPDATE','SKIP'), result_id。UNIQUE (job_id, sheet_code, row_no)。

### export_log
id, company_id, user_id, export_type, filters_json, columns_json, row_count, file_url（7 天删文件留记录）, at。

## 第十三组：设备和同步

### device
id, company_id, site_id, type（八种）, name, serial, device_key_hash, paired_to_device_id, last_seen_at, status check in ('ACTIVE','OFFLINE','DISABLED'), app_version, config_json。

### sync_batch
id（客户端批次号）, company_id, device_id, user_id, received_count, applied_count, duplicate_count, error_count, errors jsonb [{client_id, code, message}], received_at。

## RLS 策略

| 表 | 策略 |
|---|---|
| 所有带 company_id | company_id = current_setting('app.company_id')::uuid。应用账号无 BYPASSRLS |
| permission, import_template, role 模板行 | 不启或允许 company_id is null 可读 |
| 跨公司报表 | 不存在。超管也先设 app.company_id |

## 建表顺序

1. permission, import_template
2. company → 触发器插虚拟位置
3. site → zone → category → zone_category → location
4. tax_code → supplier → product → barcode → price_history → product_supplier → product_site_setting
5. app_user → role → role_permission → user_site_role
6. movement_reason_enabled → movement → stock → expiry_lot → shelf_assignment
7. approval_request → import_job → import_row → export_log
8. device → sync_batch
9. audit_log（分区）
10. 触发器、RLS、授权
