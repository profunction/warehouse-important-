# 第一阶段详细规格 第 4 节：离线同步协议

## 五条原则

1. 本地先写再上传。屏幕立刻反馈，上传在后台。
2. 账本只增不改，没有冲突。两台手机离线各自收货，两条都算。
3. 主数据以服务器为准。手机只读副本，不改主数据。
4. 每条记录有客户端编号，重传安全。
5. 服务器是最后一道校验。不通过的隔离并开工单，不丢弃不静默接受。

## 拉取协议 GET /sync/pull?entities=&cursor=

| 规则 | 说明 |
|---|---|
| 游标 | 不透明字符串，每实体最大 updated_at + id |
| 增量 | updated_at > 游标，含 is_active = false 行。无物理删除 |
| 分页 | 每次 ≤2000 行，has_more |
| 范围 | 按站点角色过滤。成本价只给有权限者 |
| 首次 | 游标空全量。1000 产品 2-3 MB，Wi-Fi 10 秒 |
| 频率 | 前台每 60 秒；收到推送立即；push 成功后；进扫描屏前（超时 2 秒用本地） |
| 失败 | 静默重试。24 小时未成功首页红条"数据超过一天未更新"，功能照用 |
| 权限变更 | me 实体 updated_at 更新，下次拉取重画首页。停用返回 401 登出清缓存 |

## 推送协议 POST /sync/push

请求：
```
{ "batch_id", "device_id", "app_version", "device_time",
  "items": [ { "client_id", "entity", "op": "insert|upsert|attach_photo", "seq", "payload" } ] }
```
响应：
```
{ "batch_id", "server_time",
  "results": [ { "client_id", "status": "applied|duplicate|rejected|quarantined", "server_id"?, "code"?, "message_zh/ms/en"?, "ticket_id"? } ],
  "new_cursor" }
```

| 规则 | 说明 |
|---|---|
| 顺序 | 按 seq 处理 |
| 批次 | ≤200 条或 1 MB，上一批成功再发下一批 |
| 幂等 | (entity, client_id) 已存在 → duplicate。movement 的 client_id = id |
| 事务 | 每条独立提交 |
| 时钟 | 偏差 >5 分钟响应带 clock_skew_seconds，手机黄色提示。performed_at 存手机时间，synced_at 服务器时间 |
| 照片 | POST /sync/photos 单张 multipart，成功后 op = attach_photo 更新引用 |
| 重试 | 5 秒、30 秒、2 分、10 分、30 分，之后每 30 分；网络恢复和回前台立即 |
| 超时 | 30 秒，整批重发靠幂等 |

### 四种结果

| 状态 | 服务器 | 手机 |
|---|---|---|
| applied | 已写入 | 删 outbox |
| duplicate | 已存在 | 同上 |
| rejected | 可由用户修正的校验失败 | 留 outbox 标红，角标"1 条需处理"，修改或删除（二次确认） |
| quarantined | 用户不能修正（权限收回、货位停用、PO 取消） | 删 outbox。服务器存 sync_quarantine 并开工单给经理 |

### 服务器校验顺序

1. 批次：device ACTIVE，令牌有效属该公司，app_version ≥ 最低（否则整批拒绝要求更新）。
2. client_id 已存在 → duplicate。
3. 格式必填 → rejected。
4. 引用对象存在且 active 属该公司站点 → 不存在 rejected，停用 quarantined。
5. 用户在 performed_at 当时有权限（permission_history）→ 无 quarantined。
6. 插入，触发器再校验，抛错 → quarantined。

## 冲突规则

| 实体 | 规则 |
|---|---|
| movement | 全部追加 |
| shelf_assignment | 按 assigned_at 最后为准。不同货架两条都留，晚的 is_primary。同货架 duplicate |
| goods_receipt_line | 追加，同 GRN 同产品合并数量并标注 |
| count_line | 取 counted_at 晚的，早的标 superseded |
| 用户设定 | 手机为准 |
| 主数据 | 服务器为准，不上传 |

## 认证

| 项目 | 规则 |
|---|---|
| 令牌 | 12 小时，刷新令牌 7 天。离线过期仍可操作，上线先刷新再上传。刷新也过期要求在线登录，outbox 保留 |
| 设备密钥 | Keystore，每次 push 签名 batch_id + device_time |
| 本地加密 | SQLCipher |
| 远程停用 | 设备 DISABLED → 423，手机清库显示"此设备已停用" |
| 多用户一机 | 每用户 outbox 缓存分开，未上传记录跟用户 |

## 边界情况

| 情况 | 处理 |
|---|---|
| 两机离线补同一产品同一货架 | 两条 REFILL 都生效，shelf_assignment 一 applied 一 duplicate |
| 离线时产品被停用 | quarantined，经理重新启用后"重试" |
| 离线时 PO 取消 | quarantined |
| 卸载重装 | outbox 丢失。登录时告知上次同步时间并开工单。预防：outbox >50 条或 >4 小时未传首页红色提示 |
| 手机时间改到过去 | 接受，日结以 synced_at 为准，记 clock_skew |
| 同码 2 秒内两次 | 手机端去重 |
| 上传中断网服务器已写 | 重发得 duplicate |
| 服务器维护 | 503 + Retry-After，不算失败 |
| 存储不足 | 停止拍照提示 |

## 监控

| 指标 | 来源 | 告警 |
|---|---|---|
| 设备最后同步 | device.last_seen_at | 工作时间 >2 小时 → 工单经理 |
| outbox 积压 | push 带 pending_count | >100 条或最老 >8 小时 → 工单 |
| quarantined | sync_quarantine | 每条工单，每日汇总老板 |
| rejected 比例 | sync_batch | 单设备单日 >10% → 工单 |
| 时钟偏差 | sync_batch.clock_skew | >5 分提示，>1 小时工单 |
| 版本过低 | device.app_version | 拒绝上传提示更新 |
