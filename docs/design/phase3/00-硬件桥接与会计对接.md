# 第三阶段预先决定：硬件桥接、会计对接、不换 ERP

日期：2026-11-18

## 1. 不换成 ERPNext 或 Odoo

评估结论：保留自己的系统。理由：一线员工的一屏一事、离线先写后传、盲盘、模板开店和多租户隔离是现有系统的核心，两个 ERP 都没有；ERPNext 是 GPL-3，卖软件副本要开源改动；第一阶段已完成并通过验收。

从这些项目借用的：Odoo 的 POS 硬件兼容清单当采购参考；ERPNext 的马来西亚电子发票社区 App 当 MyInvois 实现参考（接入前逐行审查）。

## 2. 硬件桥接服务（收银电脑本地）

POS 网页不直接碰硬件。每台收银电脑跑一个本地服务 `wh-bridge`（Node.js），监听 `ws://127.0.0.1:9123`，POS 网页通过 WebSocket 发指令。

| 设备 | 连接 | 库 | 指令 |
|---|---|---|---|
| 收据打印机 80mm | USB、网口 TCP 9100、蓝牙 | node-escpos | print(receipt)：中文不乱码（GB18030 或打印机内置字库）、Logo、MyInvois 二维码 |
| 钱箱 | 打印机 RJ11 口 | node-escpos | openDrawer()，现金付款自动触发 |
| 扫码枪 | USB HID 键盘模式 | 浏览器全局监听（已在手机端实现） | 不走桥接 |
| 客显 / 顾客副屏 | 第二个浏览器窗口或 HDMI 副屏 | 浏览器 BroadcastChannel | 显示清单、总额、付款后显示电子发票二维码 |
| 电子秤（收银台） | 串口 RS-232 或 USB 转串口 | serialport | readWeight()，稳定后回传 |
| 标签秤（称重区） | 独立打印带重量条码 | 无需连接 | POS 解析条码（已实现） |
| 标签打印机 | 蓝牙或 USB | 手机端走系统打印 PDF；收银机走桥接 TSPL/ZPL | printLabel(pdf 或 zpl) |
| 支付终端 | 第三阶段不直连 | | 只记金额和参考号 |

要求：每种设备在网页端有配置页和"测试"按钮；断线自动重连；错误用三语提示；提供模拟设备模式，没有硬件也能开发和演示；桥接服务随 Windows 开机自启，有托盘图标显示状态。

安卓平板收银：优先用 Capacitor 壳里的蓝牙打印插件；浏览器直连可用 WebUSBReceiptPrinter 作备选。

## 3. 会计对接

不自己写总账和报税。第三阶段做与库存直接相关的部分：POS 收据、企业客户发票、收付款、对账单、供应商发票三方匹配、MyInvois 提交。

总账走两条路之一（待老板回答后定）：
- 导出对接：每日或每月导出销售、收款、采购、付款的 Excel 或 CSV，格式按 SQL Account 或 AutoCount 的导入模板。
- API 对接：推送到 ERPNext 或 Odoo 只当账本，不用它们的前台。
