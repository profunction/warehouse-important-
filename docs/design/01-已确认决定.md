# 第一部分：已确认的决定

| 项目 | 决定 | 对设计的影响 |
|---|---|---|
| 国家 | 马来西亚 | 电子发票走 LHDN MyInvois。POS 收据按月做合并电子发票，顾客要求时才开个人电子发票。企业发票逐张提交验证并打印二维码。货币 MYR，现金找零按 0.05 取整，SST 税码按产品设定。 |
| 现有 POS | A 模式没有，B 模式用 Pandal | A 模式自建 POS。B 模式以 Pandal 为销售记录来源：推产品和价格给它，拉销售记录扣库存。需向供应商索取 API 文档。若没有 API，用导出文件自动导入。 |
| 老板通知渠道 | Telegram | 审批、每日低库存清单、工单提醒、AI 机器人全走同一个 Telegram 机器人。审批用按钮。 |
| 站点与客户 | 卖给其他公司，两个模式都要 | 多租户：每张表带 company_id，行级安全隔离。同一套软件，只是开关不同。 |
| 产品规格 | 需要海鲜等称重商品 | 产品增加计量单位（件或公斤），数量允许三位小数。支持标签秤条码和收银台电子秤两种方式。 |
| 多条码 | 允许 | 条码独立成表，每个条码带换算数量。 |
| 批次到期 | 默认 | 收货记到期日，提供即将到期清单，不按批次分库存。 |
| 店内结构 | 默认 | 每店一个后仓加多个货架位置。补货是后仓到货架的移动。POS 扣货架库存。 |
| 负库存 | 默认 | POS 不阻止销售，库存可为负，自动开盘点工单。 |
| 供应商对接 | 默认 | PO 以 PDF 电邮或 WhatsApp 发出。无门户，无 EDI。 |
| 付款方式 | 默认 | 现金、卡、电子钱包，只记金额，不对接刷卡终端。 |
| 设备 | 需要联机设备 | 设备登记表：扫描枪、电子秤、标签打印机、收据打印机、钱箱、大屏。绑定站点，掉线开工单。 |
| 部署 | 全系统兼顾在线和离线 | 每个 App 本地先存后同步。客户端生成 UUID，服务器去重。账本只增不改。审批类动作必须在线。 |
| 语言 | 默认 | 简体中文、马来文、英文。 |
| 企业客户 | 默认 | 30 天信用期，月对账单，允许部分付款，统一价格表。 |
| 审批层级 | 默认 | 一层审批一个角色。老板批订单，经理批盘点差异，会计批供应商付款。 |
| AI 机器人 | 默认 | App 内和 Telegram，文字和语音，云端大语言模型。 |
| 成本可见 | 默认 | 超管、老板、采购、会计看成本。经理看毛利率不看成本。 |
| 多台 POS | 一家店多台收银机 | 每台是独立 Device，共享店库存。收据号 = 店代码 + 机号 + 流水。详见 06。 |
| 老板代理 | 老板不在时可授权他人代批 | 有时限、范围、金额上限，记录标明代批。详见 04。 |
