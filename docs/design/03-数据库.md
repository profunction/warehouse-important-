# 第三部分：数据库表和关联

## 五条全局规则

1. 每张业务表都有 company_id。数据库开行级安全（RLS），请求带公司编号，自动只看到自己公司的行。A、B 模式同一套表，差别在 Company.plan 和功能开关。
2. 主键用 UUID，由客户端生成。离线能产生编号，上传按编号去重。所有表有 created_at、created_by、updated_at、updated_by。
3. Movement 表只能插入。禁止 UPDATE 和 DELETE。写错再插反向记录。Stock 由触发器维护，应用无写权限。
4. 数量 decimal(14,3)。金额 decimal(14,2)，MYR。
5. 不物理删除主数据。产品、位置、用户、供应商用 is_active 停用。

## 关键查询

- 扫条码查库存：Barcode → Product → Stock 按 location 分组 → Location → Zone → Site。
- 大屏找货：Product → ShelfAssignment → Location（本店 SHOP）→ MapElement 坐标。只回 qty > 0 布尔值。
- 每日低库存：Product + ProductSiteSetting 最低量 对比 Stock 汇总，Movement 取 30 天 SALE 算日均。
- 三方匹配：PurchaseOrderLine.unit_cost × GoodsReceiptLine.received_qty 对比 SupplierInvoiceLine。
- 损耗：Movement reason = COUNT 或 ADJUST 且到 DAMAGED 或负差，乘 unit_cost。

## A、B 模式差别只在数据

| 项目 | A | B |
|---|---|---|
| Site | 1 个 SHOP | N 仓库 + N 店 |
| Zone | 模板固定 A 到 F 加 S | 自定义 |
| Role 启用 | BOSS、CASHIER、WAREHOUSE（库存员） | 全部 9 个 |
| 审批者 | 全部 BOSS | 按类型 |
| Transfer、CountRule、Customer、Invoice、SupplierInvoice | 开关关闭 | 启用 |
| Sale.source | OWN_POS | PANDAL |
