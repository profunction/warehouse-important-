# 并行开发规范（第二到四阶段，五路同时开发）

## 必读：项目结构和约定
- pnpm 单仓：`packages/db`（SQL 迁移和种子）、`packages/server`（Fastify 5 + pg + zod）、`packages/app`（React 18 + Vite PWA + Dexie 离线）、`packages/shared`（权限码、三语错误、类型、主题）。
- 设计文档：`docs/design/02-工作流程.md`（每个流程的步骤和数据变化，**按它做**）、`04-角色权限.md`、`05-屏幕清单.md`（屏幕编号 C/W/K/S/P/M/O/D/G/A）、`06-API清单.md`（路径和权限）、`03-数据库.md`。
- 老人规则：一屏一任务、最多 3 步、按钮 ≥72px、正文 22px、三语（zh/ms/en，用 `useT()` 的 `t`、`t2`、`n`）、颜色永远配图标和文字、错误用 `ErrorScreen`（整屏红）、完成用 `DoneScreen`。
- 库存**只能**通过 `applyMovement`（`packages/server/src/lib/movements.ts`）写入；永远不要直接改 `stock` 表。
- 所有写入接口接受 `client_id`（幂等）。离线操作走 outbox：前端 `enqueue({ client_id, entity, op, user_id, payload, summary })`，服务器在模块里 `registerSyncHandler(entity, handler)`（`lib/syncHandlers.ts`）。
- 审批：`lib/approvals.ts`。建审批 `createApproval(tx, ctx, { type, ref_type, ref_id, summary, amount })`；模块启动时 `registerApprovalHandler(type, async (tx, ctx, a, decision) => …)` 处理批准后的动作；决定统一走 `POST /approvals/:id/decide`（由"盘点审批"路线实现）。代理人逻辑已在引擎里。
- Telegram：`lib/telegram.ts` 的 `tgSend(companyId, html, buttons, { type, refType, refId })`。没配置 token 时自动写 `notification` 表（测试可断言）。
- 单据编号：`nextDocNo(tx, companyId, kind, prefix, scope)`（`lib/docno.ts`），例如 `nextDocNo(tx, cid, 'PO', 'PO-2026-')`。
- 权限：`requirePerm('a','b')` 任一；`hasPerm(ctx, code)`；成本字段用 `stripCost(ctx, row)`；超管 `ctx.isSuperAdmin`。功能开关 `company.feature_flags`（transfers、cycle_count、b2b_invoice、kiosk、pandal、own_pos、einvoice_consolidated），关闭时返回 `AppError(403, 'FEATURE_DISABLED')`。
- 数据库：事务用 `withCompany(cx(req), async (tx) => …)`（RLS 按 company_id）；`adminPool` 绕过 RLS（只在跨公司或定时任务用）。新表已在 `packages/db/migrations/010–012` 建好，**先读你模块相关的表定义**。如确需加字段，新建 `013_<模块>.sql`，并对开发库跑 `node packages/db/scripts/migrate.mjs`。
- 定时任务：`lib/jobs.ts`（pg-boss）。各模块在自己的 `lib/<模块>Jobs.ts` 里导出 `registerXxxJobs(boss)`，由 `jobs.ts` 的 `startJobs` 调用（你需要在 jobs.ts 里加一行调用；只加一行，别动其他）。
- 错误码：`packages/shared/src/messages.ts`（已预加常用码）。需要新码时**只追加**在文件末尾 `INTERNAL` 之前，三语。
- 前端字符串：你模块的 key 放在 `packages/app/src/i18n/ext/<模块>.ts`（已建空文件），格式 `key: [zh, ms, en]`。不要改 `strings.ts`。
- 前端手机屏幕模板在 `packages/app/src/ui/Shell.tsx`（TopBar、Confirm、ErrorScreen、DoneScreen、QtyPad、ExpiryPicker、ProductHead、SyncBars）和 `ui/Scanner.tsx`；条码解析、本地库存、outbox 在 `screens/mobile/flow.ts` 和 `offline/db.ts`。参考 `screens/mobile/Receive.tsx`、`Refill.tsx`、`Putaway.tsx` 的写法。
- 网页端页面在 `screens/web/pages/`，已在 `index.ts` 注册了占位组件，你直接覆盖对应文件。工具函数在 `pages/_util.ts`。样式用现有类名（`.web table`、`.btn`、`.form`、`.tabs`、`.pill`、`.toolbar`、`.cards .stat`、仪表板的 `.dash .panel`）。
- 手机占位屏幕在 `screens/mobile/`（路由已在 `App.tsx` 接好，首页按钮映射已在 `Home.tsx` 的 ROUTE 表），直接覆盖对应文件。

## 测试
- 服务器：`packages/server/test/<你的文件>.test.ts`，vitest 对真实 Postgres。**用你自己的测试库**：`cd packages/server && DATABASE_NAME=warehouse_test_<模块> pnpm exec vitest run test/<文件>`（globalSetup 会重建该库并建超管 admin@test.local / 123456）。在 `beforeAll` 里用超管建自己的公司（`POST /admin/companies`，short_code 唯一，plan 按需要 A 或 B），再用老板登录（`POST /auth/login { company_code, phone, pin }`）。参考 `test/phase1.test.ts` 和 `test/helpers.ts`。
- 类型检查：`pnpm --filter @wh/server exec tsc --noEmit -p .` 和 `pnpm --filter @wh/app exec tsc --noEmit -p .` 必须通过。
- 端到端：开发栈 `bash e2e/up.sh`（Postgres、API tsx watch 自动重载、Vite 5173）。示范公司 DEMO1：老板 0120000001/111111，库存员 0120000009/222222，收银员 0120000008/333333，超管 admin@demo.local/123456。登录方式见 `e2e/web-shot.mjs`。写 `e2e/<模块>-smoke.mjs`（Playwright，`reducedMotion: 'reduce'`，截图到 `e2e/shots/`）。**不要**改 DEMO1 的公司设定或主题，**不要**重启共享的 API 服务（tsx watch 会自动重载）。

## 禁止
- 不要 git commit / push（由主会话统一提交）。
- 不要改不属于你的文件（见各自任务里的"你拥有的文件"）。共享文件只允许"追加一行"的有：`lib/jobs.ts`（调用你的 registerXxxJobs）、`shared/src/messages.ts`（追加错误码）。
- 不要改 `migrations/001–012`、`seeds/001–005`、`lib/movements.ts`、`lib/approvals.ts`、`lib/telegram.ts`、`routes/sync.ts`、`App.tsx`、`Home.tsx`、`pages/index.ts`、`strings.ts`、`styles.css`（样式需要时写在你自己的 `screens/<模块>/<模块>.css` 并在组件里 import）。
- 不要问主会话问题；设计文档没写的按常识定，写进你文件顶部的注释。
